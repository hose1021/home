# ADR 0001 — Кодированные ошибки на границе server actions

Дата: 2026-08-25 · Статус: принято

## Контекст

Модули финансов бросают ошибки с готовыми сообщениями. После миграции на next-intl появились два анти-паттерна: `getTranslations()` внутри server actions для конструирования текстов ошибок и жёстко русские строки в сервисах. Сервис — слой без UI, язык пользователя ему знать не положено; но и actions не должны дублировать бизнес-правила, чтобы понять, что именно пошло не так.

## Решение

Сервисы бросают `PaymentError` (и родственные типизированные ошибки) с машинным кодом (`not_found`, `immutable_status`, …). Server action ловит ошибку на границе и переводит код в сообщение на языке пользователя через next-intl.

## Следствия

- Сервисы не импортируют `next-intl`; их тесты не зависят от локалей.
- Добавление языка = добавление сообщений в `messages/*.json`, без изменений сервисов.
- Код ошибки — часть интерфейса модуля: меняя код, меняешь и ключ перевода.
